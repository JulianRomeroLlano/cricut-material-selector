# Test Plan — Cricut Material Selector Web App
**Version:** 1.0  
**Date:** 2026-06-06  
**Scope:** All client-side functionality — data loading, ML inference, search/filter UI, prediction UI, localization.

---

## 1. App Overview (Test Context)

Two primary user flows:

| Flow | Description |
|------|-------------|
| **A — Known Material** | User searches/browses the 1039-row material table and reads official cut settings |
| **B — Unknown Material** | User inputs material properties → ML model predicts pressure, blade, multi-cut |

Five machines: Cricut Joy, Cricut Joy 2, Cricut Joy Xtra, Explore 3, Maker 3.  
Two languages: English (default), Japanese (browser `navigator.language` starts with `"ja"`).

## 4. Acceptance Criteria

All tests in sections 3.1–3.9 must pass before the app is considered shippable.  
Critical (must pass, zero tolerance):

- **D-01–D-08** — data integrity
- **M-01–M-05** — model loads and produces valid shapes
- **P-06, P-07, P-08, P-09** — core prediction happy path
- **S-02, S-04, S-13** — core search happy path
- **L-01, L-02** — localization minimum
- **X-01, X-02, X-03** — no white screens on asset failures

Non-critical (allowed to defer to post-launch):

- A-03–A-05 (accessibility enhancements)
- R-04, R-05 (tablet/desktop polish)
- L-11 (in-session language toggle)

## 5. Test Implementation Approach

Tests will be implemented in Step 6 as:

| Layer | Tool | Files |
|-------|------|-------|
| Unit (encoding, decode) | `qunit` or plain `<script type="module">` assertions | `tests/unit.html` |
| Integration (model pipeline) | Browser console script + onnxruntime-web | `tests/model_test.html` |
| UI smoke tests | Manual checklist executed in Chrome DevTools | `tests/manual_checklist.md` |
| Data integrity | Node.js script run once on JSON build | `tests/check_data.js` |

No build step required — all tests run from `file://` or local dev server.
